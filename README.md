# ウェディング用プロフィールブック

## 1. 概要

このプロジェクトは、結婚式のプロフィールブックをウェブで実現するためのサンプルプロジェクトです。
静的なHTML, CSS, JavaScriptで構築されており、新郎新婦のプロフィールや馴れ初め、写真などのコンテンツは `content.json` という単一のファイルで管理されています。これにより、コードを直接編集することなく、非エンジニアでも容易にコンテンツの更新が可能です。

## 2. プロジェクト構成

本プロジェクトの主要なファイルとディレクトリの役割は以下の通りです。

```
.
├── README.md               # このファイル
├── index.html              # メインとなるHTMLファイル
├── style.css               # 全体的なスタイルシート
├── site-designs.css        # サイトのデザインに関する追加のスタイルシート
├── script.js               # メインのJavaScriptファイル
├── carousel.js             # 写真カルーセル機能のスクリプト
├── seating-chart.js        # 席次表機能のスクリプト
├── dialog.js               # ダイアログ表示機能のスクリプト
├── content.json            # プロフィールやメッセージなどのコンテンツを定義するJSONファイル
├── images/                 # サイトで使用する画像ファイル
└── animation/              # アニメーション関連のコード
```

## 3. 開発ルール

本プロジェクトを開発する上でのルールを定めます。

### 3.1. 基本方針

- **言語:** コメントやコミットメッセージを含め、開発に関わる言語は原則として**日本語**を使用します。
- **設計思想:**
    - **変更への強さ:** 将来の機能追加やデザイン変更に柔軟に対応できるよう、関心の分離を意識します。
    - **ベタ打ちの回避:** 設定値や表示コンテンツなどのハードコーディングは極力避け、`content.json` のような外部ファイルや設定変数で管理します。
    - **堅牢な作り:** エラーハンドリングや入力値の検証を適切に行い、安定した動作を目指します。

### 3.2. ブランチ戦略

Gitのブランチは、以下の命名規則で運用します。

- `main`: 本番環境にデプロイされる安定版のブランチ。直接のコミットは禁止し、`develop`ブランチからのマージのみ許可します。
- `develop`: 開発のベースとなるブランチ。`main`ブランチから分岐し、機能開発が完了したブランチがマージされます。
- `feature/[issue-xx-]description`: 新機能の開発を行うブランチ。`develop`から分岐します。（例: `feature/add-guest-message-form`）
- `fix/[issue-xx-]description`: バグ修正を行うブランチ。`develop`から分岐します。（例: `fix/carousel-image-not-loading`）
- `refactor/description`: リファクタリングを行うブランチ。`develop`から分岐します。（例: `refactor/separate-js-modules`）

### 3.3. コミットメッセージ

コミットメッセージは[Conventional Commits](https://www.conventionalcommits.org/)の規約に準拠します。
これにより、コミット履歴の可読性を高め、変更内容を追いやすくします。

**フォーマット:**
```
<type>(<scope>): <description>
```

**主な`<type>`:**

- `feat`: 新機能の追加
- `fix`: バグ修正
- `docs`: ドキュメントの変更（README.mdなど）
- `style`: コードスタイルの変更（フォーマット、セミコロンなど）
- `refactor`: コードのリファクタリング（機能的な変更なし）
- `test`: テストの追加・修正
- `chore`: ビルドプロセスや補助ツールの変更など、ソースコードやテスト以外の変更

**例:**
```
feat(profile): 新郎の趣味の項目を追加
fix(dialog): ダイアログが閉じた後も背景がスクロールできない問題を修正
docs(readme): 開発ルールに命名規則を追加
```

### 3.4. 命名規則

可読性と一貫性を保つため、以下の命名規則に従います。

- **ファイル名:** `kebab-case` (例: `seating-chart.js`)
- **変数名・関数名:** `camelCase` (例: `loadContent`, `userName`)
- **クラス名:** `PascalCase` (例: `ProfileCard`, `ImageCarousel`)
- **定数名:** `UPPER_SNAKE_CASE` (例: `MAX_GUESTS`, `API_ENDPOINT`)

### 3.5. コーディングスタイル

- **インデント:** スペース2つで統一します。
- **フォーマッター:** 将来的にはPrettierやESLintを導入し、コードスタイルを自動で統一することを目指します。手動でフォーマットする場合は、上記のルールと一般的な慣習に従ってください。
